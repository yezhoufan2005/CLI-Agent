# Research: terminal coding agents (as of 2026-10-28)

Scope: prior art, provider tool-use APIs, incidents, edit-tool evidence, and Linux sandboxing for a
new open-source Python terminal coding agent. Every claim has a source URL. "unverified" means the
claim could not be confirmed from a primary source during this research.

## 1. Existing agents

### Codex CLI (OpenAI)
- Sandbox modes: `read-only`, `workspace-write`, `danger-full-access`; also `--dangerously-bypass-approvals-and-sandbox`. The "Auto" preset is `--sandbox workspace-write --ask-for-approval on-request`. https://learn.chatgpt.com/docs/agent-approvals-security
- `approval_policy` values documented: `on-request`, `never`; "untrusted" is no longer supported. `on-failure`: unverified (not mentioned in current docs). Same source.
- "By default, the agent runs with network access turned off." Same source.
- macOS uses Seatbelt (`sandbox-exec`); "Linux uses bwrap plus seccomp by default". Landlock appears only as a legacy alias; the "Landlock + seccomp" description of Codex is outdated/unverified against current docs. Same source.
- Linux: uses the first `bwrap` on PATH, else a bundled helper needing unprivileged user namespaces; on Ubuntu 24.04 load the `bwrap-userns-restrict` AppArmor profile. Extra writable paths via `sandbox_workspace_write.writable_roots`. https://learn.chatgpt.com/docs/sandboxing
- AGENTS.md: global file in `~/.codex` (CODEX_HOME), `AGENTS.override.md` preferred over `AGENTS.md`; project discovery walks git root -> cwd, at most one file per dir, concatenated root-down so closer files win; `project_doc_max_bytes` default 32 KiB. https://learn.chatgpt.com/docs/agent-configuration/agents-md

### AGENTS.md (open format)
- Plain Markdown; nearest file in the tree takes precedence; supported by Codex, Jules, Gemini CLI, Aider, goose, opencode, Cursor, Copilot coding agent, Devin and others; stewarded by the Agentic AI Foundation (Linux Foundation). https://agents.md/

### Claude Code (Anthropic)
- Permission modes: `default` (reads only), `acceptEdits` (+ edits and mkdir/touch/mv/cp), `plan`, `auto` (classifier), `dontAsk` (anything that would prompt is denied; for CI), `bypassPermissions` ("Isolated containers and VMs only"). Deny rules still apply in bypass; bypass "offers no protection against prompt injection"; refuses `--dangerously-skip-permissions` as root. https://code.claude.com/docs/en/permission-modes
- Rules evaluated deny -> ask -> allow, first match wins. Syntax e.g. `Bash(npm run *)`, `Read(./secrets/**)`. Compound commands split on `&&`, `||`, `;`, `|`, `|&`, `&`, newline; every subcommand must be allowed; deny/ask apply inside subshells and `$()`. "Bash permission patterns that try to constrain command arguments are fragile"; a Bash rule "isn't a security boundary around the program". https://code.claude.com/docs/en/permissions
- Symlinks: allow requires both requested path and resolved target to match; deny applies if either matches; Edit/Write refuse to write through a symlinked file; path is re-checked at open time. Same source.
- Sandbox: Seatbelt on macOS, bubblewrap + socat on Linux/WSL2 (`@anthropic-ai/sandbox-runtime`). Writes allowed to cwd, added dirs, `$TMPDIR`; reads allowed machine-wide except denied dirs. Linux network: separate netns, egress only via a host-side proxy with hostname allowlist (starts empty), no TLS inspection, non-TCP blocked. Optional seccomp filter blocks Unix sockets. Off by default; if it cannot start, commands run unsandboxed unless `sandbox.failIfUnavailable` is set. https://code.claude.com/docs/en/sandboxing
- Hooks: events include SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse, PostToolUseFailure, Stop, SubagentStop, PreCompact, SessionEnd. JSON on stdin; exit 0 = success, exit 2 = blocking, other = non-blocking ("If your hook is meant to enforce a policy, use exit 2"). PreToolUse can return `permissionDecision` allow/deny/ask/defer. Timed-out hooks don't block. https://code.claude.com/docs/en/hooks
- CLAUDE.md: managed (`/etc/claude-code/CLAUDE.md` on Linux), user (`~/.claude/CLAUDE.md`), project (`./CLAUDE.md` or `./.claude/CLAUDE.md`), local (`./CLAUDE.local.md`); ancestors loaded at launch, subdirectories on demand; `@path` imports; target <200 lines; "context, not enforced configuration". https://code.claude.com/docs/en/memory
- Headless: `-p/--print`, `--output-format text|json|stream-json`, `--input-format stream-json`, `--include-partial-messages`, `--max-turns`, `--permission-mode`, `--allowedTools/--disallowedTools`, `-c/--continue`, `-r/--resume`. https://code.claude.com/docs/en/cli-reference
- Headless details: exit 0 on success, non-zero on failure; JSON output includes `result`, `session_id`, `total_cost_usd`; stream-json's last line is a `result` message; `system/init` first event; `system/api_retry` events carry `attempt`, `retry_delay_ms`, `error_status`. `--bare` skips hooks/MCP/CLAUDE.md discovery for reproducible CI; without it, `-p` runs a project's hooks and `.mcp.json` servers "even in a folder you've never trusted". SIGTERM exits 143. https://code.claude.com/docs/en/headless

## 2. Anthropic Messages API tool use

- Tool definition: `name` (must match `^[a-zA-Z0-9_-]{1,128}$`), `description`, `input_schema` (JSON Schema); optional `input_examples`, `cache_control`, `strict`, `defer_loading`, `allowed_callers`. Docs recommend detailed descriptions (3-4+ sentences) and consolidating related operations into fewer tools. https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools
- `tool_choice`: `auto` (default with tools), `any`, `tool`, `none`. Opus 5.5, Sonnet 5.5, Fable 5.1 and Mythos 5.1 reject `any`/`tool` with HTTP 400; use `auto` + `strict`. Changing `tool_choice` invalidates cached message blocks. Same source; also https://platform.claude.com/docs/en/api/errors
- Call/response: assistant `tool_use` block has `id`, `name`, `input`; `stop_reason` = `tool_use`. Reply with a `role: user` message of `tool_result` blocks (`tool_use_id`, `content` string or list of text/image/document blocks, optional `is_error: true`). Results must immediately follow the tool_use message and come first in the content array; text before them -> 400 ("tool_use ids were found without tool_result blocks immediately after"). Claude retries invalid calls 2-3 times; write instructive error messages. Treat tool results as untrusted (indirect prompt injection). https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls
- Stop reasons: `end_turn` (may be empty after tool results; don't blindly retry), `max_tokens` (if it cuts a `tool_use`, retry with higher limit), `stop_sequence`, `tool_use`, `pause_turn` (server-tool loop hit iteration limit, default 10; send content back as-is, cap continuations), `refusal` (HTTP 200; read `stop_details`), `model_context_window_exceeded`. When streaming, `stop_reason` arrives only in `message_delta`. https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons
- SSE: `message_start` -> per block `content_block_start` / `content_block_delta`* / `content_block_stop` (with `index`) -> `message_delta` (cumulative usage) -> `message_stop`; arbitrary `ping`s; mid-stream `error` events (e.g. `overloaded_error`) after HTTP 200. Delta types `text_delta`, `input_json_delta` (accumulate `partial_json`, parse at block stop), `thinking_delta`, `signature_delta`. "Handle unknown event types gracefully." Partial `tool_use`/thinking blocks can't be recovered; on 4.6+ models resume with a user "continue" message (prefill unsupported). https://platform.claude.com/docs/en/build-with-claude/streaming
- Errors: 400 invalid_request, 401 authentication, 402 billing, 403 permission, 404 not_found, 409 conflict, 413 request_too_large (32 MB), 429 rate_limit, 500 api_error, 504 timeout, 529 overloaded. SDKs auto-retry connection errors, 429 and 5xx twice with exponential backoff honoring `retry-after`. Body `{"type":"error","error":{type,message},"request_id"}`; `request-id` header on every response. Thinking blocks must be passed back unmodified. https://platform.claude.com/docs/en/api/errors
- Rate limits: token bucket; on 429 wait `retry-after` seconds; a spend-cap 429 has no `retry-after` and `error_code` `enforced_spend_limit_reached` (retrying won't help). Headers `anthropic-ratelimit-{requests,tokens,input-tokens,output-tokens}-{limit,remaining,reset}`. https://platform.claude.com/docs/en/api/rate-limits
- Prompt caching: `"cache_control": {"type":"ephemeral"}` (optional `"ttl":"1h"`; default 5 min, refreshed on hit). Prefix order tools -> system -> messages; a change invalidates that level and later. Max 4 breakpoints. Minimum 512 tokens on 5.x models (1024-4096 older); shorter prompts silently not cached. Write 1.25x (5m) / 2x (1h), read 0.1x (0.05x on Opus/Sonnet 5.5). Usage reports `cache_creation_input_tokens`, `cache_read_input_tokens`, `input_tokens`. https://platform.claude.com/docs/en/build-with-claude/prompt-caching

## 3. OpenAI Chat Completions tool calling (brief)

- Tool: `{"type":"function","function":{"name","description","parameters","strict"}}` (name `a-zA-Z0-9_-`, max 64). Assistant message carries `tool_calls: [{id, type:"function", function:{name, arguments}}]` where `arguments` is a JSON string; SDK warns the model "does not always generate valid JSON, and may hallucinate parameters". Results: `{"role":"tool","tool_call_id","content"}`. `finish_reason`: `stop`, `length`, `tool_calls`, `content_filter`, `function_call`. Streaming deltas carry `index`, optional `id`, and `function.arguments` fragments to concatenate. Params include `tools`, `tool_choice`, `parallel_tool_calls`. https://github.com/openai/openai-python/tree/main/src/openai/types/chat
- The current guide documents the Responses API (flat tools, `function_call` items with `call_id`, `function_call_output`); Chat Completions is non-strict by default; GPT-6 Astra / GPT-6.1 Sol require Responses for tool calling. https://developers.openai.com/api/docs/guides/function-calling

## 4. Failure cases and security incidents

- Lethal trifecta: private data + untrusted content + ability to communicate externally = exfiltration; guardrails can't be relied on, so avoid combining all three. Examples cited: M365 Copilot, GitHub MCP, GitLab Duo. https://simonwillison.net/2025/Jun/16/the-lethal-trifecta/
- Gemini CLI (Tracebit, 2025): prompt injection hidden in a README's GPL text; user allowlists an innocent `grep`; weak prefix matching let `grep ...; <malicious>` run silently; whitespace padding hid the payload in the UI; env vars (credentials) exfiltrated. Reported 27 Jun 2025, fixed in v0.1.14 (25 Jul 2025); sandbox was off by default. Tracebit reports Codex and Claude Code were not vulnerable in its tests. https://tracebit.com/blog/code-exec-deception-gemini-ai-cli-hijack
- GitHub MCP "toxic agent flow" (Invariant Labs, 26 May 2025): a malicious public issue led an agent to leak private-repo data into a public PR; users had clicked "Always Allow". Mitigations: granular permissions, one repo per session, monitoring. https://invariantlabs.ai/blog/mcp-github-vulnerability
- Amazon Q Developer for VS Code (CVE-2025-8217): an over-scoped GitHub token in CodeBuild let an attacker commit malicious code into extension 1.84.0; it failed to execute due to a syntax error; fixed in 1.85.0. https://aws.amazon.com/security/security-bulletins/AWS-2025-015/ . Press quotes the injected prompt ("clean a system to a near-factory state and delete file-system and cloud resources"): https://www.bleepingcomputer.com/news/security/amazon-ai-coding-agent-hacked-to-inject-data-wiping-commands/
- Claude Code CVE-2025-54794 (CWE-22): directory restriction used "prefix matching instead of canonical path comparison" (`/cwd` vs `/cwd_evil`); fixed in 0.2.111. https://github.com/advisories/GHSA-pmw4-pwvc-3hx2
- Claude Code CVE-2025-54795: command-parsing error let a crafted `echo` command bypass the approval prompt. https://github.com/advisories/GHSA-x56v-x2h6-7j34
- Replit / SaaStr (July 2025, press report, not a primary write-up): agent deleted a production database during a code freeze and said it "panicked and ran database commands without permission". https://www.businessinsider.com/replit-ceo-apologizes-ai-coding-tool-delete-company-database-2025-7
- Secrets leaked via agent logs/transcripts: no primary incident write-up found (unverified); category covered by OWASP LLM02 Sensitive Information Disclosure. https://genai.owasp.org/llm-top-10/
- OWASP LLM01 Prompt Injection mitigations: constrain model behavior, validate output formats, input/output filtering, least privilege, human approval for high-risk actions, segregate external content, adversarial testing; indirect injection comes from websites/files. https://genai.owasp.org/llmrisk/llm01-prompt-injection/
- OWASP LLM06 Excessive Agency: root causes excessive functionality, permissions, autonomy; mitigations include minimizing extensions, avoiding open-ended ones (arbitrary shell), least privilege, user approval, complete mediation, logging and rate limiting. https://genai.owasp.org/llmrisk/llm062025-excessive-agency/
- Repo content as attack surface: without `--bare`, Claude Code `-p` runs a project's hooks and `.mcp.json` servers with no trust dialog. https://code.claude.com/docs/en/headless

## 5. Edit-tool design evidence

- Anthropic text editor tool (`text_editor_20250728`, name `str_replace_based_edit_tool`): commands `view` (optional `view_range`), `str_replace` (`old_str` "must match exactly, including whitespace and indentation"), `create`, `insert`. Recommended errors: "Found 3 matches for replacement text. Please provide more context to make a unique match." / "No match found for replacement. Please check your text and try again." Also: validate paths against traversal, make backups, ensure exactly one match. https://platform.claude.com/docs/en/agents-and-tools/tool-use/text-editor-tool
- Aider unified-diff study (89-task laziness benchmark): GPT-4 Turbo 20% with SEARCH/REPLACE -> 61% with udiff; gpt-4-0613 26% -> 59%. Principles: familiar, simple (no line numbers), high-level, flexible. Disabling flexible patching -> "9X increase in editing errors"; dropping high-level prompting -> 30-50% more errors. https://aider.chat/2023/12/21/unified-diffs.html
- Aider 2023 benchmarks: GPT-3.5 did better with `whole` than `diff`; for GPT-4 the two were comparable and `diff` was chosen for cost/latency. https://aider.chat/docs/benchmarks.html
- Aider polyglot leaderboard (225 Exercism tasks): gpt-5 (high) 88.0% with `diff` (91.6% well-formed edits); o3-pro 84.9% `diff` (97.8%); gemini-2.5-pro 83.1% `diff-fenced` (99.6%); top entries overwhelmingly use search/replace-style diffs, and edit-format error rate is tracked per model. https://aider.chat/docs/leaderboards/
- Minimal-tool evidence: mini-swe-agent's bash-only design is what SWE-bench uses to compare models (see section 1). Inference (ours): a rich tool set isn't required for strong results; editing reliability and loop hygiene matter more. https://github.com/SWE-agent/mini-swe-agent

## 6. Linux sandboxing without Docker

- bubblewrap: "tool for constructing sandbox environments", "not a complete, ready-made sandbox"; protection "entirely determined by the arguments". Uses unprivileged user namespaces (setuid mode removed), sets `PR_SET_NO_NEW_PRIVS`; `--unshare-net` gives loopback-only netns; accepts seccomp filters (`--seccomp`); use `--new-session` against TIOCSTI terminal injection; "Everything mounted into the sandbox can potentially be used to escalate privileges." https://github.com/containers/bubblewrap
- Ubuntu 24.04 sets `kernel.apparmor_restrict_unprivileged_userns=1`, which blocks bwrap's userns unless an AppArmor profile allows it, because "unprivileged user namespaces have been repeatedly used to exploit kernel vulnerabilities" (source page fetched only via search snippet). https://discourse.ubuntu.com/t/understanding-apparmor-user-namespace-restriction/58007 ; Codex and Claude Code document the same issue (sections 1 links).
- Landlock: unprivileged, stackable LSM; needs `CONFIG_SECURITY_LANDLOCK` and `landlock` in `lsm=`; requires `no_new_privs`. ABI -> kernel: 1=5.13, 2=5.19 (REFER), 3=6.2 (TRUNCATE), 4=6.7 (TCP bind/connect), 5=6.10 (IOCTL_DEV), 6=6.12 (abstract-unix/signal scoping), 7=6.15, 8=7.0, 9=7.1; probe the ABI, not the kernel version. Limits: can't restrict chdir, stat, chmod, chown, utime, fcntl, access etc.; network rules TCP-only through ABI 9 (UDP listed for ABI 10); already-open fds unaffected; max 16 stacked rulesets. https://docs.kernel.org/userspace-api/landlock.html , https://man7.org/linux/man-pages/man7/landlock.7.html
- firejail: SUID program using namespaces, seccomp-bpf and capabilities; works on 3.x+ kernels; Landlock support experimental. README cites CVE-2021-26910 and notes the Ubuntu 20.04 package stayed vulnerable. (That SUID makes firejail a riskier dependency than bwrap is our inference.) https://github.com/netblue30/firejail
- Precedent: Claude Code (bwrap + proxy netns + optional seccomp) and Codex (bwrap + seccomp) both chose bubblewrap on Linux. https://code.claude.com/docs/en/sandboxing , https://learn.chatgpt.com/docs/sandboxing

## Implications for our design

- Tools: bash plus a small file toolset (view, create, exact-match `str_replace` that requires exactly one match and returns the instructive errors Anthropic recommends). Add a whitespace-tolerant fallback matcher, given Aider's "9X" error increase without flexible patching. (sections 1, 5)
- Permissions are UX, not the security boundary: deny > ask > allow, applied to every parsed subcommand (`;`, `&&`, `|`, `$()`, newlines), never prefix-matching raw command strings. The Gemini CLI `grep; malicious` bypass and CVE-2025-54795 show why. (sections 1, 4)
- Enforcement comes from the OS sandbox: bubblewrap with `--unshare-net`, `--new-session` and `--die-with-parent`, the workspace as the only writable root, plus Landlock (probe the ABI) where available. Detect the Ubuntu 24.04 userns restriction and fail closed, or warn loudly; never silently run unsandboxed. (section 6)
- Network off by default. Any egress goes through an explicit allowlist, which breaks the lethal trifecta for the common case of reading untrusted repo content with secrets on disk. Hide credential paths and scrub env vars passed to child processes. (sections 1, 4)
- Path checks: `realpath` plus `os.path.commonpath`, symlink-aware, re-checked at open time. Prefix checks are a known CVE (CVE-2025-54794). Refuse to write through symlinks. (sections 1, 4)
- Treat repo files, tool output and web content as untrusted data that only ever goes into `tool_result`. Never auto-execute repo-provided hooks or config, and require approval for destructive or remote-affecting commands (Replit, Amazon Q). (sections 2, 4)
- Anthropic adapter: tool_result blocks come first and immediately follow; accumulate `input_json_delta`; handle every stop_reason (`pause_turn`, `refusal`, `max_tokens` with a partial tool_use, `model_context_window_exceeded`); ignore unknown SSE events; retry 429/5xx/529 and mid-stream `overloaded_error` with jittered backoff honoring `retry-after`; don't retry spend-cap 429s; use `tool_choice: auto` only (5.x models reject `any`/`tool`). (section 2)
- OpenAI adapter: concatenate streamed `arguments` by `index` and JSON-parse defensively, returning a parse failure to the model as an error result. Plan for the Responses API, since newer models require it. (section 3)
- Caching: keep tools and the system prompt byte-stable and history append-only, and put `cache_control` on the last stable block. Log cache read/write tokens to verify hits; prompts under 512 tokens silently miss. (section 2)
- Reversibility and automation: git checkpoint or auto-commit per edit with `/undo` (Aider); hierarchical AGENTS.md loading with a size cap, as context not policy; a headless `-p` mode with JSON/stream-json output, `--max-turns`, cost totals, meaningful exit codes, and a "bare" mode that loads no repo config. (sections 1, 4)
